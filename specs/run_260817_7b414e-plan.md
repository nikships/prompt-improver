# Prompt Improver → Electron + Droid SDK

Rewrite the Swift/SwiftUI `droid exec` app into a native macOS Electron app (React + TypeScript) powered by `@factory/droid-sdk`. Replace the single-shot improve call with a multi-turn session: compose → agent questions → grounded prompt.

Do not keep a Swift process, a local HTTP backend, or `droid exec`. The SDK runs inside Electron main.

## Goal

A focused Factory-branded macOS app that:

1. Opens on a compose screen only (draft, repo, model, reasoning). No empty result pane.
2. On submit, transitions to a session screen. The agent scans the selected repo read-only and asks clarifying questions via the SDK `askUserHandler`.
3. Renders those questions as a polished one-at-a-time questionnaire (topic, single/multi, custom answer).
4. Resumes the same session with answers and repeats if the agent asks again.
5. Shows the final improved prompt with copy / use-as-draft / start over.
6. Cancels immediately (interrupt + close the session).
7. Remembers last repo, model, and reasoning.

## Non-goals

- Foundry-style daemon manager, MCP servers, worktrees, traces, or readiness checklists.
- Shipping a Factory API key in the renderer. Auth stays in main; the Node SDK uses the user's existing `droid` CLI login.
- Editing the selected repository. Scan is read-only.
- Windows/Linux packaging in this pass (code may run, but package macOS only).
- Keeping any Swift sources, SwiftPM, or SwiftLint.

## Architecture (locked)

Use the **Node runtime**, not Foundry's daemon path.

```
Renderer (sandboxed React)
    ↕ typed IPC (preload bridge)
Main (Node)
    createSession() from @factory/droid-sdk/node
    session.stream(prompt, { abortSignal })
    askUserHandler  → park Promise → IPC pendingAsk → resume with answers
    permissionHandler → allow reads, deny writes
```

Why Node `createSession` and not `connectToDaemon`:

- This app is one session, one window, no in-process MCP.
- Foundry's daemon path is required only for multiplexed sessions + HTTP MCP. It also hits a real 0.7.0 landmine: `oauth: false` plus an exact protocol-version gate (`FACTORY_PROTOCOL_VERSION` `1.151.0` vs current CLI `1.162.0`). Do not copy that stack.
- `droid exec` cannot park mid-turn for AskUser. The SDK session can.
- Reference implementation for Electron + SDK patterns: `/Users/nik/repos/foundry` (`src/main/droid/sdk/*`, `src/main/readiness/ask-user.ts`, `src/preload/bridge.ts`, `electron.vite.config.ts`). Copy the **shape** (typed IPC, sandboxed renderer, OLED chrome, login-shell PATH). Do not copy the daemon, readiness modal, or auto-answer policy.

Pinned SDK: `@factory/droid-sdk@0.7.0` (what Foundry has verified).

## UX (locked)

Three screens, one window. No tabs. Transitions are 220ms ease-out slides (`compose` slides left to `session`; `session` fades to `result`). Cancel / Start over slides back to compose with the draft preserved.

### Screen 1 — Compose (`idle`)

On launch, only this screen. Do **not** render an output panel.

Layout, top → bottom, OLED `#020202`:

- Hidden-inset title bar, Factory logo centered (reuse `docs/assets/factory-logo-dark.svg`).
- Numbered section `01 / DRAFT` + large monospaced textarea. Placeholder: `Describe what you want the AI to do…`. Min height ~240px. `⌘↩` submits.
- Compact control row, not a settings page:
  - **Repo**: path chip + `Choose` (native directory dialog). Whole window is a drop target for a folder. Hint: `or drop a folder anywhere`.
  - **Model**: menu of Default + builtins + `~/.factory/settings.json` custom models.
  - **Reasoning**: `Off | Low | Medium | High | Extra high | Max`.
- Primary CTA `Improve →`. Disabled until a repo is selected and the draft is non-empty.

Persist on change: `lastRepositoryPath`, `selectedModelId`, `reasoningEffort`.

### Screen 2 — Session (`starting` → `scanning` → `asking` → `resuming`)

Immediately after submit. Top context bar (always visible):

- Repo name (not full path; full path in tooltip)
- Model + reasoning
- Elapsed `12s`
- Ghost `Cancel`

Two interior states, same screen:

**Scanning (centered, calm — not a chat dump)**

- Droid glyph + uppercase mono `SCANNING REPOSITORY`
- One live activity line from the latest tool (`Read README.md`, `Glob package.json`). Keep at most the last 4 as a quiet stack.
- Do not stream assistant tokens here. The user is waiting for questions or a result, not a transcript.

**Asking (the product surface)**

When `askUserHandler` fires, scanning collapses to a 28px status strip and the questionnaire takes the stage.

Do **not** copy Foundry's readiness dropdowns. Build a focused questionnaire:

- Eyebrow: `A few questions to ground this prompt` + `2 / 4`
- One question at a time.
- Topic as Factory numbered label: `01 / SCOPE` (from `question.topic`).
- Question text at ~18px primary, not a form label.
- **Single-select** (`multiSelect` falsy): full-width option rows. Selected row gets accent border `#EE6018`. Keys: `↑↓` / `1–9` / `Enter`.
- **Multi-select** (`multiSelect === true`): checkable rows, hint `Select all that apply`. `Enter` advances only if ≥1 selected or a custom answer is filled.
- Every question also has a collapsed `Or write your own` field. Opening it deselects options (single) or is appended (multi: `selected, custom`).
- Footer: `Back` (within this batch) + primary `Next` / `Submit answers` on the last item.
- Previous rounds collapse into `Earlier answers` (topic + answer chips). A new AskUser batch starts the wizard again at question 1 of the new batch.

Submit is blocked until every question in the current batch has a non-empty answer.

### Screen 3 — Result (`complete`)

- Section `IMPROVED PROMPT`
- Selectable monospaced prompt body (the only assistant text the user is meant to take)
- Actions: `Copy` (toast `Copied` for 2s), `Use as draft` (back to compose, draft = result, result cleared), `New prompt` (back to compose, draft kept as the original)
- Collapsed `How we got here`: answered Q&A, so the user can see why the prompt is shaped that way
- Error state (`failed`): danger banner + `Retry` (same inputs) + `Edit draft` (back to compose)

Cancel from scanning or asking: interrupt, close session, return to compose with draft intact. No error banner for a user cancel.

## Session state machine

```
idle
  → starting          // createSession
  → scanning          // stream() running, no pending ask
  → asking            // askUserHandler parked
  → resuming          // answers sent, stream continues
  → scanning | asking // more tools / another ask batch
  → complete          // result message, success
  → failed            // thrown / result.success === false
  → cancelled         // user cancel; then idle
```

Only one session at a time. A new Improve while live is ignored. Cancel is the only escape.

### AskUser (do not invent a schema)

SDK 0.7.0 wire shape (`AskUserQuestionSchema` / `AskUserResultSchema`):

```ts
type AskUserRequestParams = {
  toolCallId: string;
  questions: Array<{
    index: number;
    topic: string;
    question: string;
    options: string[];
    multiSelect?: boolean;
  }>;
};

type AskUserResult = {
  cancelled?: boolean;
  answers: Array<{ index: number; question: string; answer: string }>;
};
```

Handler contract:

1. Normalize with `parseAskUser(params)` in `src/main/droid/ask-user.ts` (tolerant of missing `topic` / `multiSelect` so older payloads still render).
2. Allocate `askId`, push `pendingAsk` on the session snapshot, emit `improver:state`.
3. Return a Promise. Resolve only from `answerAsk`.
4. On user submit, resolve `{ answers }` where each `answer` is a single string. Multi-select: join with `, `. Custom-only: the typed string. Never invent a first-option default.
5. On cancel / session teardown: resolve `{ cancelled: true, answers: [] }` (do not leave the SDK hanging).
6. If `questions` is empty, treat as one open question with `question` fallback `""` and no options.

Foundry's `src/main/readiness/ask-user.ts` is the park/resume pattern to copy. Its types are incomplete (no `topic` / `multiSelect`) — do not reuse those interfaces.

Without a handler the SDK declines AskUser. That would silently skip the whole feature.

### Permissions (read-only)

`src/main/droid/permissions.ts`

- Allow immediately: `Read`, `Grep`, `Glob`, `LS`, `AskUser`, `TodoWrite`.
- Deny everything else, including `Execute`, `Create`, `Edit`, `ApplyPatch`, and unknown tools. Comment: `Prompt Improver is read-only`.
- Return a `proceed_*` option the request actually offered (Foundry `proceedOption` in `src/main/droid/sdk/policy-adapters.ts`). Never return a bare enum the ask did not list — the SDK converts that to cancel.
- Flatten `params.toolUses[0]` the same way Foundry does (`toolUse.name` + `input` + `details`).

### Stream + cancel

```ts
const controller = new AbortController();
for await (const message of session.stream(fullPrompt, { abortSignal: controller.signal })) {
  // tool start/end → activity lines
  // result → complete / failed
}
```

Cancel path (must be prompt, no leftover billing):

1. `controller.abort()`
2. `await session.interrupt()`
3. `await session.close()`
4. Clear `pendingAsk` by resolving cancelled
5. Snapshot → `cancelled` then `idle`

`createSession` / `stream` must run with a repaired `PATH` (see Locate droid). Pass `env` if the SDK option exists; otherwise set `process.env.PATH` for the app process once at startup (Foundry `src/main/system/env.ts`).

### Locate droid

`src/main/droid/find-droid.ts` — port `DroidRunner.findDroid`:

1. `~/.npm-global/bin/droid`
2. `~/.local/bin/droid`
3. `/opt/homebrew/bin/droid`
4. `/usr/local/bin/droid`
5. login-shell `command -v droid` (`/bin/zsh -lc`), fenced so motd cannot pollute the path

Also merge those dirs plus a login-shell PATH into the process PATH at startup so `droid` can spawn `node`.

Missing binary → `failed` with: `Could not find the droid CLI. Install it and make sure it is on your PATH.`

### Improvement prompt

`src/main/droid/prompt.ts` — replace the current `DroidRunner.improvementInstructions` with a two-phase instruction. Keep the original rewrite rules; add a mandatory AskUser phase.

Required behavior in the prompt text:

1. Shallow read-only scan first (README, top-level tree, manifests). No deep file-by-file dive. Do not modify anything.
2. Identify ambiguities in the draft (goal, scope, audience, constraints, success definition, UX vs backend, etc.).
3. Ask **one** AskUser questionnaire of 2–4 targeted questions before writing the final prompt. Use `topic`, real options, `multiSelect` when several answers can be true. Prefer concrete repo-grounded choices over open trivia.
4. After answers, write **only** the final improved prompt: goal, repo-grounded stack/conventions, UX + coding guidance, constraints, acceptance criteria. Mention files only when highly confident. No preamble, no commentary, no fences around the whole answer.

The draft is appended after a `---` delimiter, same as today.

### Models

`src/main/models.ts` — port `ModelCatalog.swift`:

- Builtins: `claude-opus-5`, `claude-sonnet-5`, `gpt-5.3-codex` (same ids/labels as today)

## IPC contract

`src/shared/ipc-contract.ts` + `src/shared/types.ts`. Named invokes only. No generic `invoke`. Renderer never sees `fs`, `child_process`, or the SDK.

```ts
// invokes
improver.getState(): ImproverState
improver.start(input: { draft: string; repoPath: string; modelId: string; reasoningEffort: ReasoningEffort }): ImproverState
improver.answerAsk(answers: AskAnswer[]): boolean
improver.cancel(): void
improver.chooseRepo(): string | null          // native dialog, also writes prefs
improver.setRepo(path: string): { ok: true } | { ok: false; error: string }
improver.listModels(): ModelOption[]
improver.getPrefs(): Prefs
improver.setPrefs(patch: Partial<Prefs>): Prefs
improver.copy(text: string): void             // clipboard in main

// push
improver:state  // ImproverState snapshot, on every transition / activity tick
```

`ImproverState` (renderer-safe):

```ts
type SessionPhase =
  | 'idle' | 'starting' | 'scanning' | 'asking' | 'resuming'
  | 'complete' | 'failed' | 'cancelled';

type ImproverState = {
  phase: SessionPhase;
  draft: string;
  repoPath: string | null;
  modelId: string;
  reasoningEffort: ReasoningEffort;
  elapsedSeconds: number;
  activity: Array<{ id: string; text: string; at: number }>;
  pendingAsk: PendingAsk | null;
  answered: Array<{ topic: string; question: string; answer: string }>;
  result: string;
  error: string | null;
};

type PendingAsk = {
  askId: string;
  questions: Array<{
    index: number;
    topic: string;
    question: string;
    options: string[];
    multiSelect: boolean;
  }>;
};

type AskAnswer = { index: number; answer: string };
```

Preload: `src/preload/bridge.ts` — Foundry pattern (`contextBridge.exposeInMainWorld`, typed `FoundryApi`-style object). Sandbox on.

Drop-folder: preload exposes `getPathForFile(file: File): string` via Electron `webUtils.getPathForFile`. Renderer never reads `file.path`.
