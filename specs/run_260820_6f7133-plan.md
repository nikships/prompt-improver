# Plan: Prompt for a missing Factory API key

## Goal

Prevent an improvement session from reaching the Droid SDK without credentials. When `FACTORY_API_KEY` is absent, show a renderer-owned password dialog before any session starts, accept a key, keep it only in main-process memory for the lifetime of the app, and pass it explicitly as `apiKey` to `createSession`.

## Locked behavior and security decisions

- Treat a non-empty, trimmed `process.env.FACTORY_API_KEY` as already configured. In that case, do not show the dialog.
- If no environment key exists, open the API-key dialog on initial renderer load. The user may cancel it to continue editing the draft, but every **Improve** or **Retry** attempt must reopen the dialog and must not transition into `starting` until a key has been accepted.
- If the dialog was opened by an Improve/Retry attempt, successfully submitting a key immediately resumes that pending attempt. If it was the launch-time prompt, submission only closes the dialog; it does not start a session without a valid draft and repository.
- Keep a user-entered key in a module-private variable in Electron main for the current app process only. Do not add it to `Prefs`, `ImproverState`, `StartSessionInput`, local storage, logs, error messages, or the JSON prefs file. A future app launch without `FACTORY_API_KEY` prompts again. Secure persistent credential storage is outside this request.
- Send the typed key across a dedicated IPC invoke exactly once when it is submitted. Renderer code may hold it only in the dialog input while the dialog is open; clear the input after submit or cancel. IPC status responses expose only whether a key is configured, never the key itself.
- Validate only that the value is a string whose trimmed form is non-empty. Do not invent or enforce a Factory key prefix/format.
- Main remains authoritative: even if renderer preflight is bypassed or races, the `START` IPC handler and session manager must refuse to create a session when no key is configured. Missing credentials must leave the session idle instead of surfacing the current SDK error.

## Shared contracts

### `src/shared/types.ts`

Add credential/start result types without placing credential material in shared session state:

- `FactoryApiKeyStatus` with `configured: boolean`.
- `SetFactoryApiKeyResult` as a discriminated union:
  - `{ ok: true; status: FactoryApiKeyStatus }`
  - `{ ok: false; error: string }`
- `StartSessionResult` as a discriminated union:
  - `{ ok: true; state: ImproverState }`
  - `{ ok: false; reason: 'api-key-required' }`

Keep `Prefs`, `ImproverState`, and `StartSessionInput` unchanged so a key cannot accidentally be persisted, echoed in state-change events, or retained with a draft.

### `src/shared/ipc-contract.ts`

Add named channels:

- `GET_FACTORY_API_KEY_STATUS: 'improver:getFactoryApiKeyStatus'`
- `SET_FACTORY_API_KEY: 'improver:setFactoryApiKey'`

Extend `ImproverApi` with:

- `getFactoryApiKeyStatus(): Promise<FactoryApiKeyStatus>`
- `setFactoryApiKey(apiKey: string): Promise<SetFactoryApiKeyResult>`

Change `ImproverApi.start` to return `Promise<StartSessionResult>` rather than a bare `ImproverState`. No API should provide a way to read the configured key.

## Main-process credential ownership

### New file: `src/main/factory-api-key.ts`

Create a small, independently testable credential module:

- Hold an entered key in a module-private `string | null` variable.
- `getFactoryApiKey(): string | null`:
  1. Trim `process.env.FACTORY_API_KEY` and return it when non-empty.
  2. Otherwise return the in-memory entered key.
  3. Otherwise return `null`.
- `getFactoryApiKeyStatus(): FactoryApiKeyStatus` returns only `{ configured: getFactoryApiKey() !== null }`.
- `setFactoryApiKey(value: unknown): SetFactoryApiKeyResult` rejects non-string/blank values with `Enter a Factory API key.`; otherwise trims and stores the value and returns the configured status.
- Export a test-only reset function (following the existing `__set...ForTest` convention) that clears only the in-memory value. Tests must restore the original environment variable separately.
- Never log the supplied value or include it in thrown errors.

Environment credentials take precedence over an in-memory key. The UI only prompts when no environment key exists, so this ordering is deterministic and avoids silently overriding an operator-provided environment value.

### `src/main/ipc.ts`

Register handlers for both new channels:

- Status handler returns `getFactoryApiKeyStatus()`.
- Setter passes the IPC argument through `setFactoryApiKey()` and returns its discriminated result.

Make the existing `START` handler credential-aware:

1. Check `getFactoryApiKey()` before calling `improverSession.start`.
2. If absent, return `{ ok: false, reason: 'api-key-required' }` and do not mutate or emit session state.
3. If present, await the manager and return `{ ok: true, state }`.

Do not place the API key into the START payload; session code reads it only from the main-process credential module.

### `src/main/droid/session.ts`

Make SDK session creation explicitly authenticated and independently guarded:

- Add an `ApiKeyProvider` type (`() => string | null`) and accept it as the optional second constructor dependency after `SessionFactory`, defaulting to `getFactoryApiKey`. This keeps tests deterministic and avoids using a developer’s real environment credential.
- In `start`, preserve the existing draft/repository validation and live-session duplicate guard, then resolve the API key before changing the state to `starting` or locating `droid`.
- If the provider returns no non-empty trimmed key, return the unchanged state immediately. Do not start the timer, call `findDroid`, call the SDK, or set the phase to `failed`.
- Add `apiKey` with the trimmed resolved value to the `CreateSessionOptions` passed to `this.sessionFactory`.
- Do not add the key to activity, error handling, snapshots, or listener emissions.

The IPC preflight provides the user-facing prompt; this manager check is defense in depth for direct/test callers and guarantees the SDK’s “No Factory API key found” exception is never the missing-key control flow.

## Preload bridge

### `src/preload/bridge.ts`

Implement the two new `ImproverApi` methods with the named IPC channels and update `start` to return `StartSessionResult`. Import the new shared types as needed. Continue exposing only the typed narrow bridge; do not expose Electron environment access or generic IPC.

## Renderer flow

### `src/renderer/store/improver.tsx`

Extend the provider with API-key gate state and actions while keeping the key itself out of context:

- Add `apiKeyPromptOpen: boolean` and a `pendingStartAfterApiKey: boolean` internal flag.
- Expose:
  - `submitFactoryApiKey(apiKey: string): Promise<string | null>` where `null` means success and a string is the displayable validation error.
  - `dismissFactoryApiKeyPrompt(): void`.
- During the existing initial-load effect, call `getFactoryApiKeyStatus()`. If `configured` is false, open the dialog with no pending start. This check runs alongside loading state/models/prefs and does not alter `ImproverState`.
- Extract the current START invoke into a private `runStart` callback using the current draft, repository, model, and reasoning values. Handle its union result:
  - `ok: true`: no extra local state work is required; normal main-process state events drive the screen transition.
  - `reason: 'api-key-required'`: set `pendingStartAfterApiKey` and open the dialog.
- In `startImprove` (and therefore `retry`), retain the draft/repository guard, call `getFactoryApiKeyStatus()` before `runStart`, and open the dialog instead of invoking START when unconfigured. The typed START result remains a second authoritative guard.
- On successful `submitFactoryApiKey`, close the dialog. If `pendingStartAfterApiKey` was true, clear the flag and call `runStart` immediately. Return setter validation errors to the dialog without closing it.
- On dismiss, close the dialog and clear the pending-start flag so canceling never launches later.
- Do not save the submitted string in provider state, prefs, draft state, or session state.

### New file: `src/renderer/components/ApiKeyDialog.tsx`

Add a focused modal dialog rendered with semantic `role="dialog"`, `aria-modal="true"`, and an associated title/description:

- Title: `Factory API key required`.
- Description: `Enter a Factory API key to start an improvement session. You can also launch Prompt Improver with FACTORY_API_KEY set.`
- Add a `type="password"` input labeled `API key`, with `autoFocus`, `autoComplete="off"`, and placeholder `Enter your Factory API key`.
- Add supporting copy: `The key is kept in memory for this app session and is never added to your prompt or preferences.`
- Use a `<form>` so Enter submits. Disable the primary `Continue` action while the trimmed input is empty or submission is in flight.
- Add a ghost `Cancel` action. Escape and Cancel invoke `onDismiss`; backdrop clicks should not silently dismiss the credential gate.
- Display the string returned from `onSubmit` as an inline danger message while keeping focus available for correction.
- On a successful submit or any dismiss, immediately clear the local input/error state. The component must never print the key.

Props should be explicit: `open`, async `onSubmit(apiKey)`, and `onDismiss`.

### New file: `src/renderer/components/ApiKeyDialog.module.css`

Style the modal consistently with the existing OLED design:

- Fixed full-window dark translucent backdrop above drag overlays/session content.
- Centered raised panel using existing surface, border, radius, text, monospace, accent, and danger tokens.
- Visible label, password field focus border in Factory orange, supporting text, inline error, and right-aligned Cancel/Continue actions.
- Ensure the panel fits the current minimum window dimensions and remains usable if content wraps.

### `src/renderer/App.tsx`

Render `ApiKeyDialog` once inside `ImproverProvider`, as a sibling overlay to whichever compose/session/result screen is active. Read its open state and callbacks from `useImprover`. This lets the launch-time check and Improve/Retry gate share one dialog without adding an authentication phase to the session state machine.

No changes are required in `ComposeScreen.tsx` or `ResultScreen.tsx`: their existing `startImprove`/`retry` actions will use the provider gate.

## Tests

### New file: `tests/factory-api-key.test.ts`

Cover the credential module without using a real secret:

- Missing/blank environment plus no memory key reports `{ configured: false }` and returns `null`.
- A whitespace-padded environment value is trimmed, selected, and reports configured.
- A valid submitted fake key is trimmed, stored in memory, and makes status configured when the environment is absent.
- Blank and non-string submissions return `{ ok: false, error: 'Enter a Factory API key.' }` and do not configure auth.
- A non-empty environment value takes precedence over an in-memory value.
- Status/set results never contain an `apiKey` field or the supplied key string.

In `beforeEach`/`afterEach`, save and restore the caller’s original `FACTORY_API_KEY` and reset module memory so tests neither consume nor overwrite a developer credential.

### `tests/session.test.ts`

Update session tests for the new constructor dependency:

- Define a reusable fake provider such as `() => 'test-factory-api-key'` and pass it to every manager instance that proceeds past input validation. Do not rely on the test runner’s environment.
- Add a test that a missing-key provider leaves the manager idle and does not call `findDroid` or the session factory.
- In a successful mocked session test, assert that `CreateSessionOptions` includes the exact fake key in `apiKey` along with the existing options.
- Preserve all current flow, cancellation, activity, and error assertions.

There is currently no renderer component test harness/dependency in the repository. Do not introduce one solely for this change; cover the main credential logic with Vitest and verify the modal flow manually.

## Verification

Run the full repository gate and judge success by exit status:

```sh
npm run check
```

Also verify these manual Electron scenarios with fake/test credentials where possible:

1. Launch with `FACTORY_API_KEY` unset: the API-key dialog opens before a session can start.
2. Cancel the launch-time dialog: compose remains usable; entering a draft/repo and clicking Improve reopens the dialog, remains on compose, and does not show the SDK’s “No Factory API key found” failure.
3. Submit whitespace only: Continue remains disabled (and main validation still rejects a bypassed blank value).
4. Submit a non-empty key from an Improve-triggered dialog: the dialog clears/closes and the pending session starts once; the session factory receives that key via `CreateSessionOptions.apiKey`.
5. Start another improvement in the same app run: no prompt appears because the in-memory key remains configured.
6. Restart without the environment variable: the prompt appears again and no key is present in `prefs.json`.
7. Launch with `FACTORY_API_KEY` set: no dialog appears and Improve starts normally using the environment key.
8. Exercise Retry from an error state with credentials absent in a fresh run: it follows the same gate before starting.
9. Inspect renderer state events, errors, activity, prefs, and console output to confirm no API-key value is exposed or logged.

## Acceptance criteria

- A missing Factory API key is detected before `createSession` and never reaches the SDK as a missing credential.
- The user has a clear, keyboard-usable way to enter a key and continue the intended Improve/Retry action.
- Environment-based configuration continues to work without prompting.
- `createSession` receives the resolved key through its `apiKey` option.
- The exact current SDK error is no longer the normal result of clicking Improve without an environment key.
- Credentials are main-owned after submission, session-memory-only, excluded from prefs/shared state/logging, and never readable through IPC.
- Existing session behavior and the full `npm run check` gate continue to pass.
